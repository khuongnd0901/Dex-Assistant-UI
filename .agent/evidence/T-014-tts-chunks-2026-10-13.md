## Problem and resulting behavior

Chat permits4,000 Unicode code points. Supplementary characters can exceed the
TTS input-string limit. VoiceFeedback previously submitted the whole reply and
used the public playback ID as the engine callback ID, allowing old callbacks
with a reused ID to affect new playback.

Now split within runtime `getMaxSpeechInputLength()` at sentence/word boundaries
where available, preserving supplementary code points and all text. One chunk
is submitted at a time. Unique generation/chunk IDs reject duplicate/stale
completion/error/start callbacks. Only the final successful chunk completes the
whole reply; first audible-start callback is emitted once. Cancel/timeout/close
invalidate the cursor and stop queued playback; errors stop the remaining
sequence. No Chat transcript logging/storage or action routing is introduced.
Chat/output limits, provider/model/mic ownership and60s watchdog unchanged.
Long stories may still hit that total watchdog; chunking is not a latency waiver.

Primary reference accessed2026-10-13:
[Android TextToSpeech input limit](https://developer.android.com/reference/android/speech/tts/TextToSpeech#getMaxSpeechInputLength()).
Routine playback implementation, no new product/architecture decision.
