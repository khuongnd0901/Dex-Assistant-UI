## Provisioning issues diagnosed without source changes

1. `adb install -r` streaming stalled over Wi-Fi. First runner timed out after
   240 seconds; a second streaming attempt was cancelled. Main installation
   succeeded using `--no-streaming` (25,855,832 bytes in 121.866 seconds).
2. Original script reached its first reboot after passing its pre-reboot gates,
   then stalled at fixed-serial `wait-for-device` when Wireless debugging changed
   ports. The waiting process was terminated; post-boot state was captured
   independently. A subsequent full script invocation completed before/after
   reboot via an ignored, device-specific ADB wrapper. The wrapper selects only
   the expected Fold3 and caches installation only after the installed APK
   SHA-256 equals the release file; otherwise it uses non-streaming installation.
3. **Unlock verification false positive:** Samsung `cmd user is-user-unlocked 0`
   exits 255 with `Unknown command: is-user-unlocked`. The script swallows that
   exit and matches `unlocked` inside the error message. A script success message
   alone is not unlock proof. All captured successful boots additionally use
   `dumpsys user` and require `RUNNING_UNLOCKED`. Diagnose-only; script unchanged.
4. UI health is a manual snapshot: after emergency stop persisted health was
   STOPPED and FGS absent, but the displayed Voice line still showed LISTENING
   when captured after the stop request; Refresh is a separate manual operation.
   Do not interpret that stale UI line as live recording.
5. **DPC main-app update recovery FAIL:** repeated delayed health reads show
   unchanged `lastPolicyApply=1790871646122`, while main-app health advanced.
   `dumpsys activity broadcasts` records both PACKAGE_ADDED and PACKAGE_REPLACED
   delivery to the DPC RecoveryReceiver as SKIPPED with “Background execution
   not allowed”. This is direct device evidence, not an inference from emulator
   tests. The first post-install snapshot also had runtime permissions denied;
   later DPC replacement/boot reapplied them successfully. A clean first-install
   grant flow may therefore also be affected (inference; no reset/reprovision
   performed). Do not bypass this with shell grants. Source-owning Android work
   must address package-change observation/permission reapplication and rerun
   fresh-install/update acceptance; no fix was attempted here.

6. **Paused detail is misleading:** notification Pause correctly persisted
   PAUSED, but detail remained “Opening microphone probe”. Resume returned
   LISTENING with a successful probe. Diagnose only; no text/state fix attempted.
