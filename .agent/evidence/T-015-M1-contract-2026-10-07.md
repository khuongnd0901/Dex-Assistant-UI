# T-015 M1 — additive semantic action contract (2026-10-07)

## Implemented

- Backend accepts capability schema 2 and adds `CLICK_TARGET` with a strictly
  validated nested target. Schema 1 and descriptor-free legacy routing remain.
  The backend filters provider tools by advertised schema, action and configured
  app ID, rechecks planner output, and copies nested parameters immutably.
- Canonical [schema 2 contract](../../docs/DEVICE_COMMANDS_V2.md) and
  [shared fixture](../../docs/contract-fixtures/device-command-schema-2.json)
  define required app ID and selector, bounded optional role/text/context/
  ordinal, plus invalid examples. The Android test resource is byte-identical.
- Android validates schema 2 through the existing `TypedAction` decode path.
  Current production requests still advertise schema 1 and omit `CLICK_TARGET`;
  `ActionRouter` returns `CAPABILITY_UNAVAILABLE` if invoked directly. No
  semantic UI executor, gesture or live app action was enabled in M1.
