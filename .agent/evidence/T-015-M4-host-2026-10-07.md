## Instrumentation

- Android `DexLatency` events correlate recognition epoch with request ID and
  record monotonic durations for wake, STT ready→final/manual, optional speech
  end→final, route, WebSocket send→plan, UI resolution, active execution,
  confirmation wait and optional speech end→action start. Terminal events
  identify bounded local/remote/semantic/fallback path and reason. Missing
  callbacks produce no fabricated duration. Logs contain no transcript, UI
  text, prompt, audio, token or screen data.

  bounded success/failure tags. A DEBUG-only log has request ID, duration in
  microseconds, outcome and planner code. The prior broader planning timer
  remains available. No Android/server timestamp subtraction or wire change.
- [Measurement guide](../../docs/T015_LATENCY_MEASUREMENT.md) defines stage
  boundaries, correlation, nearest-rank p95, missing data and Fold3 run steps.
